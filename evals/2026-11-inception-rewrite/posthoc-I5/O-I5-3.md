**Derivation test:**
- *Forward:* the principle derives the dated `runs/` directory and arguably YAML. It doesn't derive `exp/`, the port or the version, which confirms they're plain constraints.

## Proposed output

**Principle**
Work in this repo should be reproducible and findable later. Someone should be able to locate a result by its date and rerun it from a readable config.

**Why**
Experiments are only worth as much as your ability to find and repeat them. Dated directories give a result a stable address, and YAML configs can be read and diffed by people. A shared branch prefix separates experimental work from everything else.

**Derived anchors**
- Hence: results go in `runs/YYYY-MM-DD/`.
- Hence: configs are YAML, not JSON.
- Hence: experimental branches start with `exp/`.

**Boundary**
- This covers experiment outputs and configs only. It doesn't mean moving other files into `runs/`, converting existing JSON that other tools consume, or branching for trivial edits.
- Hard constraints, which have no deeper reason and are kept as plain rules:
  - The test database runs on port 5433.
  - Python is 3.11.

## Placement

Put this in the repo's AGENTS.md or CLAUDE.md, since it applies to every session. Keep the two hard constraints in a short "Environment" list next to the principle.

If the reproducibility reason isn't why you chose these conventions, drop the principle and keep all five as a plain list. A made-up rationale would do worse than the list. I haven't written anything to a file. Tell me the destination if you want me to.
