**What I'd propose**

**Principle** — This repo is a lab notebook, not a scratch space. Every experiment should be findable and reproducible by a labmate months later, and the conventions below exist so that it is.

**Why** — Results from different people and dates only compare cleanly if they sit in predictable places and run in the same environment. That is the real reason for the date-stamped results folder, the `exp/` branch prefix, and the pinned Python. It is also the reason to say so openly. An agent that knows the goal will put a new artifact in the right place even for a case the list doesn't cover, such as logs, plots, or checkpoints.

**Derived anchors**
- Hence: results, logs, and plots go in `runs/YYYY-MM-DD/`, using the date the run happened.
- Hence: experiment work lives on branches named `exp/<topic>`.
- Hence: code targets Python 3.11, so a run reproduces on the lab's setup.

**Boundary**
- The principle covers *where experiment output goes and what it runs on*. It doesn't mean agents should log or archive everything. Don't create run folders for trivial or dry runs.
- Don't reorganize existing files to fit the notebook idea. Apply it to new work.

**Hard constraints** (arbitrary, so they stay plain rules):
- Test database port is `5433`.
- Config files are YAML, not JSON.
