**Intent:** Agents working in the lab repo should follow the repo's conventions without being reminded.

**Ladder result:** I tried to climb, and these five rules mostly don't share a deeper concept. Port 5433, `exp/` prefixes, Python 3.11, and YAML are arbitrary choices. No principle derives them, and inventing one would be fiction, which breaks the "True" requirement. Two of them have a partial, honest reason, though.

**Principle** — Lab work should be reproducible and findable by someone who wasn't there. Results and configs are shared artifacts, not private scratch.

**Why** — Experiments are only worth something if a labmate can locate a run, see what produced it, and rerun it. That depends on predictable locations, consistent formats, and a fixed environment.

**Derived anchors**
- Hence: results go in `runs/YYYY-MM-DD/`, so a run can be found by date without asking anyone.
- Hence: configs are YAML, so every experiment's settings are written in one format that people and tools can both read.
- Hence: branches start with `exp/`, so experimental work is recognizable and separate from stable code.

**Boundary**
- The principle covers where artifacts go and how they're recorded. It doesn't license reorganizing existing files, converting old JSON configs, or adding metadata the lab didn't ask for.
- If the situation is ambiguous (for example, a run that spans two dates), pick the choice that keeps the run findable, and say which you picked.

**Hard constraints (arbitrary, kept as plain rules)**
- Test database port: 5433.
- Python version: 3.11.

These two have no deeper reason I can honestly give. Dressing them up would make the frame weaker.
