The default PostgreSQL port is 5432, and no, it is not safe to expose directly to the public internet without significant precautions. Doing so exposes the database to brute-force login attempts, credential-stuffing bots that scan for open 5432 ports, and any unpatched vulnerabilities in the PostgreSQL version running. If remote access is genuinely required, it should go through a VPN, SSH tunnel, or bastion host rather than a direct public listener; access should also be restricted by firewall rules (e.g., security groups, `pg_hba.conf`) to known IP ranges, TLS should be enforced for connections, and authentication should use strong passwords or certificate-based auth rather than trust/password-only methods. Many managed cloud database offerings default to private-network-only access for this reason. In general, treat any database port—not just PostgreSQL's—as something that belongs on a private network segment, with application servers or an API layer mediating public access rather than the database itself facing the internet directly.
