The default port for PostgreSQL is **5432**.

As for exposing it directly to the public internet, that's generally **not recommended**. A few reasons why:

- **Attack surface**: An open database port is a magnet for automated scanning, brute-force login attempts, and credential-stuffing bots the moment it's reachable.
- **Vulnerability exposure**: Any unpatched PostgreSQL CVE becomes remotely exploitable if the port is public, whereas it's a non-issue on a private network.
- **Authentication risks**: Misconfigured `pg_hba.conf` (e.g., `trust` or weak `md5` auth) combined with public exposure can lead to trivial compromise.

If you genuinely need remote access, safer alternatives include:
- Placing PostgreSQL in a private subnet/VPC and only allowing your application servers to reach it (security group / firewall rules).
- Connecting via an SSH tunnel, bastion host, or VPN instead of opening the port directly.
- If you must allow direct external connections, restrict access to specific known IP addresses, enforce TLS/SSL, use strong `scram-sha-256` authentication, disable remote superuser login, and keep PostgreSQL patched.

Changing the port number away from 5432 offers only minor obscurity benefit and shouldn't be relied on as a security measure by itself — the controls above (network restriction, auth, TLS, patching) are what actually matter.
