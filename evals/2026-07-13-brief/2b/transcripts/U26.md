Most common causes, roughly in order of likelihood:

1. **Poor layer caching** — `COPY . .` before install steps, so every code change invalidates the dependency-install layer. Fix: copy only manifest files (package.json, requirements.txt, go.mod) first, install, then copy the rest.
2. **No `.dockerignore`** — huge build context (node_modules, .git, build artifacts) gets sent to the daemon every time.
3. **No BuildKit cache mounts** for package managers (`--mount=type=cache`), so apt/npm/pip re-download on every build.
4. **Not using BuildKit at all** — enable with `DOCKER_BUILDKIT=1` (default in newer Docker) for parallel stage execution and better caching.
5. **Missing multi-stage builds** — compiling/installing build-time deps in the final image instead of discarding them.
6. **No registry cache reuse** in CI — each CI run starts cold without `--cache-from`/`--cache-to`.
7. **Large/unnecessary base images** — e.g., full `ubuntu` or `node` instead of `-slim`/`-alpine`.
8. **Multi-platform builds via QEMU emulation** — cross-arch builds are dramatically slower than native.

Quickest wins: add `.dockerignore`, reorder Dockerfile so dependency install happens before `COPY . .`, and add BuildKit cache mounts.
