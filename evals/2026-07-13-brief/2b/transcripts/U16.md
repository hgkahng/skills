The most likely causes are poor layer caching, an oversized build context, and inefficient Dockerfile ordering. Specifically: copying the entire source tree before installing dependencies invalidates the cache on every code change, forcing a full reinstall; missing a `.dockerignore` sends node_modules, `.git`, and build artifacts into the context on every build; not pinning dependency-install layers separately from application-code layers means cache never gets reused; and using single-stage builds instead of multi-stage builds keeps build tools and intermediate files bloating the final image. Other common culprits: BuildKit not enabled (missing parallel stage execution and better caching), no persistent cache mounts for package managers (apt, pip, npm, cargo re-downloading every run), pulling a large or unpinned base image (e.g., full Ubuntu instead of slim/alpine), running `apt-get update` and install in separate layers instead of one combined RUN, and CI runners with cold caches (no registry cache or `--cache-from` configured). Fixes: reorder Dockerfile so dependency manifests are copied and installed before source code, add `.dockerignore`, enable BuildKit with cache mounts, use multi-stage builds, and configure CI to reuse layer cache between runs.
