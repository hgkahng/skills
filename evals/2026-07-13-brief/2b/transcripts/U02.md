Storing JWTs in localStorage is generally discouraged, mainly because localStorage is accessible to any JavaScript running on the page, which makes tokens vulnerable to theft via XSS attacks (a malicious or compromised script can simply read the token and exfiltrate it, with no way to mark it "off-limits" the way you can with cookies). The more security-conscious approach is to store tokens in an httpOnly, Secure, SameSite cookie, which JavaScript cannot read directly, and pair that with CSRF protections since cookies are sent automatically by the browser. That said, no storage location is risk-free — cookies have their own CSRF considerations — so the real priority should be minimizing XSS risk in general (via CSP, output encoding, and dependency hygiene), using short-lived access tokens with refresh rotation, and reserving localStorage, if used at all, for low-sensitivity, short-lived tokens rather than long-lived or highly privileged ones.
