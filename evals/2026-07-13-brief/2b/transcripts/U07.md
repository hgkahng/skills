No, not for a typical web app. Web apps are I/O-bound — waiting on DB/network calls — and the GIL releases during I/O, so threads/async already give you concurrency. Scaling across CPU cores is done with multiple worker processes (gunicorn/uvicorn workers), not threads, so the GIL isn't the bottleneck there either.

It does matter if you're doing CPU-bound work *inside* a process with threads (in-process ML inference, image/data crunching) — threads can't parallelize that across cores. For those cases use multiprocessing, or try Python 3.13+'s experimental free-threaded (no-GIL) build — though as of now it's still slower for single-threaded code and C-extension compatibility is incomplete, so it's not yet a safe default.
