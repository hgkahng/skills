A race condition is a bug that happens when the result of a program depends on the order or timing of events that you can't control.

It usually shows up when two parts of a program work at the same time and both touch the same data. The parts "race" to finish, and the outcome changes depending on who wins.

Here is a simple example. Say a bank account holds $100, and two people try to withdraw $80 at the same moment. Each one checks the balance and sees $100, so each one thinks the withdrawal is fine. Both go through, and the account ends up overdrawn. If the two withdrawals had run one after the other, the second would have been refused.

These bugs are hard to find because they don't happen every time. The program can work correctly a thousand times and then fail once, when the timing lines up wrong.

The usual fix is to make sure only one part can use the shared data at a time. Programmers do this with locks, which make the second part wait until the first is done. Another fix is to avoid sharing the data in the first place.
