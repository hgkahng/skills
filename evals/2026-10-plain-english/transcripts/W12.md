A race condition is a bug where a program's result depends on the timing or order in which two or more things run at once (threads, processes, or requests), and that order isn't controlled.

Typical example: two threads each read a counter holding 5, add 1, and write back 6. Both increments ran, but the counter is 6 instead of 7, because the second thread read the value before the first one wrote it.

The usual fix is to make the shared access happen one at a time, using a lock, an atomic operation, or a database transaction. Another option is to avoid sharing the data at all.
