**Idempotent** means that doing an operation more than once has the same effect as doing it once. The result after the second or tenth call is the same as after the first.

Setting a thermostat to 70° is idempotent: pressing it five times leaves it at 70°. "Raise the temperature by 1°" is not: five presses give five degrees more.

**Why people care in APIs:** networks fail. If a client sends a request and the connection drops before a response arrives, it can't tell whether the server processed it. If the operation is idempotent, the client can safely retry. If it isn't, a retry might charge a card twice or create a duplicate order.

In HTTP, `GET`, `PUT` and `DELETE` are defined as idempotent, while `POST` usually isn't. For non-idempotent operations like payments, APIs often accept an **idempotency key**, a unique ID the client attaches to the request. The server uses it to recognize a retry and return the original result instead of repeating the action.
