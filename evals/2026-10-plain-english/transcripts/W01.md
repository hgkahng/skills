A process is a running program with its own isolated memory. A thread is a unit of execution inside a process, and the threads of one process share that process's memory.

**Process**
- It has its own address space, so its code, heap, and global data are separate from every other process.
- It has its own resources, such as open file handles and a process ID.
- One process can't read or write another's memory directly. To communicate, they use inter-process communication (IPC): pipes, sockets, shared memory, message queues, and so on.
- Creating one and switching between them is relatively expensive.
- A crash in one process usually doesn't take down the others.

**Thread**
- It lives inside a process. Every process has at least one thread, and it can have many.
- Threads in the same process share the heap, global variables, and open files.
- Each thread has its own stack, registers, and program counter, so each can run its own call sequence.
- Creating one and switching between them is cheaper, and sharing data is easy because it's all in the same memory.
- That sharing causes race conditions, deadlocks, and similar bugs, so shared data needs synchronization such as locks.
- A serious fault in one thread, such as a bad memory access, can crash the whole process.

**Analogy:** A process is like a house with its own kitchen and furniture. Threads are the people living in it. They share the kitchen, which is convenient, but they can get in each other's way. Separate houses (processes) keep people apart, but passing things between them takes more effort.

**When to use which**
- Use multiple threads when tasks need to share a lot of data and work closely together, such as a UI thread alongside background workers, or a server handling many requests in one program.
- Use multiple processes when you want isolation and fault tolerance, such as a browser giving each tab its own process, or when you want to get around a language limit like Python's GIL for CPU-bound work.

The exact details vary by operating system and language runtime.
