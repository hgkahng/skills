A database index is a separate, sorted copy of one or more columns, with pointers back to the full rows. It lets the database jump straight to the rows you want instead of reading the whole table.

Without an index, a query like `WHERE email = 'a@b.com'` has to scan every row. With an index on `email`, the database searches the sorted structure and follows the pointer to the matching row.

Most indexes are B-trees. A B-tree is a balanced tree whose nodes hold sorted keys. The database starts at the root and picks the right branch at each level until it reaches a leaf, which holds the key and a pointer to the row. Even a table with millions of rows needs only 3 to 4 steps, so lookups take logarithmic time instead of linear time. Because the keys are sorted, the same structure also handles range queries (`BETWEEN`, `<`, `>`) and `ORDER BY`.

The cost is that every `INSERT`, `UPDATE` and `DELETE` must also update the index, and each index takes extra disk space. Add indexes on columns you filter, join or sort by often, and avoid indexing everything.
