A database index works like the index at the back of a book. Instead of reading every page to find a topic, you look it up in the index and go straight to the right page.

Without an index, the database has to check every row in a table to find the ones you asked for. That gets slow as the table grows. With an index, it jumps almost directly to the matching rows.

An index is a separate, sorted copy of one or more columns, with a pointer from each value back to its full row. Most databases store it as a tree (usually a "B-tree"). The tree lets the database narrow down to the right value in a few steps. A table with a million rows takes only about 20 steps to search, instead of a million.

For example, say you often run this:

```sql
SELECT * FROM users WHERE email = 'ann@example.com';
```

If you create an index on the `email` column, the database finds that one row quickly instead of scanning the whole table:

```sql
CREATE INDEX idx_users_email ON users (email);
```

The cost is that indexes take up space and slow down writes. Every time you add, change, or delete a row, the database must update the index too. So add indexes on the columns you search or sort by often, and not on every column.
