A process is a running program. A thread is a single line of work inside that process.

Each process gets its own private chunk of memory. Other processes can't see it. If one process crashes, the others usually keep running.

Threads live inside a process and share that process's memory. Because they share it, they can pass data to each other quickly. But two threads can also change the same data at the same time and cause bugs. That is the main risk of threads.

Here's a simple picture. A process is a kitchen. Threads are the cooks working in it. The cooks share the same fridge and counters, so they can hand things to each other easily, but they can also get in each other's way. A different kitchen (another process) has its own fridge and its own cooks.

Two more differences:

- Starting a new process costs more than starting a new thread, because the system has to set up a whole new memory space.
- If one thread crashes the process, every thread in it dies too.

People use threads when tasks need to share a lot of data. They use separate processes when they want strong separation, such as keeping a web browser tab from taking down the whole browser.
