Good news: this is normal React behavior, and it usually isn't a problem.

**Why it happens**

Your input almost certainly stores its text in state, like this:

```jsx
function SearchBox() {
  const [text, setText] = useState("");

  return (
    <input value={text} onChange={(e) => setText(e.target.value)} />
  );
}
```

Each keystroke fires `onChange`, which calls `setText`. Calling a state setter tells React that the state changed. React then calls your component function again (a "re-render") to get the new description of the UI. In this example, the input shows the new `text` value only because of that re-render. So the re-render on every keystroke is how a controlled input works.

**Why it's usually fine**

Re-rendering means React runs your function again and compares the result with the previous output. It only updates the parts of the real page that changed. For a small component, this takes a tiny fraction of a millisecond.

**When it can become a problem**

If the component that holds the state also contains something expensive, such as a big list, a chart, or heavy calculations, that work repeats on every keystroke. A re-render of a component also re-renders all of its children by default. Here are some fixes, from simplest to most advanced:

1. **Move the state down.** Put the input and its state in a small component of their own, so only that small component re-renders as you type.

   ```jsx
   function Page() {
     return (
       <>
         <SearchBox />      {/* has its own state, re-renders on typing */}
         <ExpensiveList />  {/* not affected */}
       </>
     );
   }
   ```

2. **Use an uncontrolled input.** If you only need the value when the user submits, skip state and read it then, using a `ref` or a form's `FormData`. Nothing re-renders while typing.

3. **Wrap expensive children in `React.memo`.** This tells React to skip re-rendering a child when its props haven't changed.

4. **Use `useMemo` or `useDeferredValue`.** These help with expensive calculations that depend on the typed text.

Try these only if you actually notice lag. Many beginners worry about re-renders that cost nothing.

**A quick way to check what's happening**

Add a `console.log("render")` at the top of your component. If you're in development with `<StrictMode>`, you may see each log twice. That's deliberate, because React renders twice in development to catch bugs, and it doesn't happen in production.
