That's normal React behavior, not a bug.

In React, a component re-renders (runs its function again) whenever its **state** changes. If your input is a "controlled input", it looks something like this:

```jsx
const [text, setText] = useState("");
<input value={text} onChange={e => setText(e.target.value)} />
```

Every keystroke calls `setText`, which changes the state, so React runs your component again to show the new value. That is how the input stays in sync with `text`.

It's usually harmless. Re-rendering is cheap, and React only updates the parts of the page that actually changed.

If it feels slow, the usual fix is to move the input and its state into its own small component, so typing doesn't re-render the rest of the page.
