This comes down to how Flask treats trailing slashes in route rules. The two URLs are different paths to Flask, and your rule only defines one of them.

When you write `@app.route('/api/items')` with no trailing slash, Flask matches only `/api/items`. A request to `/api/items/` doesn't match, so you get a 404.

The behavior is different in the opposite direction. If you had defined the route as `@app.route('/api/items/')`, with the slash, Flask would treat it like a directory. A request to `/api/items` would get a 308 redirect to `/api/items/`, and `/api/items/` would work directly. Only the route without the slash is strict, which is what you have.

You have a few ways to fix it.

**1. Define the route with a trailing slash.** This is the simplest fix if you want both URLs to work:

```python
@app.route('/api/items/')
def get_items():
    return jsonify(ITEMS)
```

`/api/items/` returns the data. `/api/items` gets redirected to it. With curl, the redirect isn't followed by default, so `curl localhost:5000/api/items` will show a 308 unless you add `-L`. That can be awkward for API clients, and some of them won't follow redirects on non-GET requests.

**2. Accept both URLs without a redirect.** Pass both rules to the same view:

```python
@app.route('/api/items')
@app.route('/api/items/')
def get_items():
    return jsonify(ITEMS)
```

Both paths return a 200 directly.

**3. Turn off strict slashes.** You can do this for a single route or for the whole app:

```python
@app.route('/api/items', strict_slashes=False)
def get_items():
    return jsonify(ITEMS)

# or for every route
app.url_map.strict_slashes = False
```

With `strict_slashes=False`, both `/api/items` and `/api/items/` return the data directly, with no redirect.

For a JSON API, option 2 or 3 is usually the better choice, because clients get a direct response either way. Whichever you pick, try to use one form consistently in the URLs you publish and in your docs.
