Generally it's not recommended. Any JavaScript running on your page, whether it's your own code, a compromised npm dependency, or an XSS hole, can read localStorage and steal the token, and a stolen JWT can be used from anywhere until it expires. The more common alternative is an HttpOnly, Secure, SameSite cookie, which scripts can't read, though you then need to handle CSRF (SameSite plus a CSRF token usually covers it). That said, localStorage is an accepted tradeoff in some cases: if you have a strict Content Security Policy, short-lived access tokens, refresh token rotation, and little sensitive data at stake, the risk may be tolerable. For anything high-value, such as banking, admin panels, or personal data, prefer HttpOnly cookies, or keep the token in memory and refresh it via a cookie-backed endpoint.
